## 3. 仍然存在的实质问题

### 3.1 新终点仍不能自动叫“完整任务成功”

修正后的规则检查功能性状态／工具轨迹里程碑以及 minefield，即预定义禁止事件，但排除了纯 AGENT→USER 回答内容。对仅关注后台状态变更的问题，这可以是合理的窄终点；对用户要求查询并告知结果的任务，返回答案属于任务本身。

例如固定版本 ToolSandbox 的 `search_phone_number_with_name`，既有查找联系人的工具轨迹要求，也有向用户提供号码的回答要求。按新定义，正确查了联系人但随后报告错误号码，仍有可能满足功能性二元终点。此处是评分规则允许的反例，不是声称已经在 R138 轨迹中发现该错误。

**不要求逐字复刻答案，不等于不检查答案是否正确。**建议分别定义并报告：工具／状态达成、最终回答的语义正确性、禁止事件、完整任务成功。若当前研究只保护第一项，就持续使用该较窄名称。把所有回答内容称为“措辞”会掩盖其中的事实要求。

来源：固定提交下的 [ToolSandbox 单工具场景](https://github.com/apple-aiml-research/ToolSandbox/blob/c8571d7854316d2e1c5f288e59fe1e34e53f6dd1/tool_sandbox/scenarios/single_tool_call_scenarios.py)。

### 3.2 包内协议和包外 V2 没有统一

包内 `R140_DECISIVE_CONTROL_EXPERIMENT_PROTOCOL_V1.md` 是有价值的设计蓝图，但模型、收益门槛、预算、重复次数和具体比较方法尚待填写。它不应单独作为已经具备全部可执行内容的冻结协议交付。

补充核对发现，包外 V2 已经给出 Qwen2.5-1.5B-Instruct、8 个候选种子、四档强度、至少 25% 能力验证准确率且较旧模型提高至少 15 个百分点、最多 20 个选择集家族，以及对候选／强度联合校准等具体内容。因此不应说团队没有做这些设计；准确的问题是：**本次交付包没有呈现一致的协议、代码、执行状态及结果对应关系。**

需要说明包内 V1 与包外 V2 哪个实际控制下一次实验，旧版本为何保留，哪些运行有效，并给出对应脚本及结果档案。不能只凭版本号判断先后或有效性。

### 3.3 包外 V2 的拒绝认证分支没有落实到代码

V2 规定校准家族不足时程序应拒绝认证。代码确实在顺序统计量越界时令 `qjoint=inf`，但在选择阶段只检查是否存在满足能力门槛的候选，没有进一步以校准不足或认证集合为空为条件停止。

只要存在可选候选，无穷 allowance 会使所有候选的下界评分归零，随后排序仍通过能力分数等规则选出 `effect_aware` 候选。它没有按协议返回拒绝认证。

需要把“未获得认证”“仍以经验规则选出候选”“允许部署”定义为不同状态。可以保留经验选优作为单独基线，但不能让它承担认证方法的成功。还应明确定义 q 有限但没有任何获认证家族、选择集为空或最终审计为空等分支。

代码定位：`qjoint` 的构造、`method_choices['effect_aware']` 的赋值及其上层 `if admissible`。本次为源码确认，不依赖是否已发生某个具体运行结果。

### 3.4 成本记录仍不足以支持“节省验证成本”

V2 比较前需要获取：旧模型基础分数、4 个候选的 pilot 分数，以及校准集上每个候选在 4 档更新强度下的完整 margin。联合 allowance 因此需要多次校准计算。

当前 `method_cost` 对 margin 方法只记录选择集的记录数，未把校准集、候选数、强度数和重复前向计算分摊进去。全局 timing 保存了部分时间，但全部实验方法一起运行的耗时不能直接变成每一种部署方法的独立成本。随机验证的记录数也需要与候选／强度评估次数区分。

建议建立逐操作成本台账，注明“哪个方法必要、是否共享、在哪一阶段发生”，同时报告唯一任务数、实际评估次数及时间。可以给出冷启动成本和明确可复用后的后续成本，但必须说明复用条件。开发最终独立审计的成本，也应与部署前选择成本分开，并用一致规则计入各方法。

### 3.5 生成与 margin 计算的输入截断规则不同

包外代码中，实际生成的 prompt 上限为 576 tokens；margin 计算则由 `768 - len(target)` 决定 prompt 预算。这意味着长输入可能在两个路径中得到不同前缀。完整目标加 EOS 的正 margin 只有在相同输入、相同目标范围和相同解码条件下，才能支持相应生成结论。

应统一生成与 margin 的输入 token 序列，并逐条记录是否截断、是否包含完整目标和停止符。这是一个条件性风险：本次没有实际 tokenizer 长度台账，不能断言哪些现有样本受影响；但当前代码没有排除它。

此外，该 runner 向模型提供的工具描述是“required parameters only”的压缩接口，省略了部分说明和可选参数。使用官方 AST 检查器是进步，但应准确称为在自定义输入接口下使用官方检查器，不能默认为完全采用官方原始评估接口。

### 3.6 语义分组方向正确，但规则仍有细节缺口

ToolSandbox 前瞻协议把“可用工具集合及 schemas”纳入家族 key，同时要求不同工具干扰／名称改写增广归属同一家族。这需要先恢复为增广前的基础任务表示，否则工具集合或名字一变，key 也会变。当前文件没有交付完成的规范化实现和最终家族清单。

包外 BFCL V2 又保留 parallel 调用顺序作为家族签名的一部分，而官方 parallel AST 匹配允许输出调用重排。对语义等价的无序调用集合，应检查是否需要排序或多重集合规范化。此处指出分组规则未排除的情形，不是断言实际冻结数据必然发生了这种泄漏。[BFCL 官方评估说明](https://gorilla.cs.berkeley.edu/blogs/8_berkeley_function_calling_leaderboard.html)

家族不跨组能降低重复问题，但并不自动证明不同家族独立、可交换。应陈述抽样机制、总体及保护筛选规则。新 ToolSandbox 方案只留 5 或 10 个最终审计家族，也主要适合可行性观察；即便假定独立，10 次零失败的单侧 95% 二项上界仍约 25.9%。不能把 10 例称为充分支持强可靠性结论的通用门槛。

### 3.7 部分理论只是加了限定语，尚未完成严格闭合

鲁棒线性恢复的凸性问题已真正修正，应认可。

但 SI 第 61 页式 S117 的对数－对数余项仍以“似然过程满足所需正则性”等概述支撑，没有给出可逐条检查的完整条件、明确算法及该强度的证明或精确引用。加入这些限定语缩小了主张，却不能替代证明。应明确一个已经可证明的模型子类；若现有证明只能支持一阶渐近式，就使用该较弱结论。

随后分阶段信息下界还需要明确：最终阶段能否使用 pilot 信息，干预 x 是否随机且依赖先前数据，以及保证是否条件于已经选择的 x。可重复利用信息时，两个单独阶段的下界不能未经论证直接相加。该问题不意味着核心 Gaussian 或线性对偶结果全部无效，而是一般化陈述需要单独完成证明。

### 3.8 当前 SI 的版本优先级文字仍过时

SI 开头及第 86 页仍以“R137 数学记录／R138 更新记录优先”为控制规则，并称 R138 不改定理。但 R140 本身已经修正了数学文字。应明确以现行 R140 修订后的正式命题和证明为准，并标记被替代的位置。

保留历史材料是正确的；读者也需要清楚知道哪些是当前主张。完整保存母版、投稿 SI 和历史版本可以有不同阅读用途，不必通过删除独特科学内容解决混淆。

## 4. 为什么 Daniel 会觉得难懂

### 4.1 更新的含义没有先分层

需要区分三个对象：商业系统中以候选模型替换原模型；开源模型中可观察和控制的继续训练；系统提示、工具或上下文的变化。

第一类不要求已知训练血缘。商业版本更替并不意味着论文知道新模型是在旧权重上训练得到。第二类才允许在已知参数空间中解释方向、幅度和路径。第三类又需要与参数更新分开报告。

Daniel 关于“新模型是否建立在旧模型上”的困惑，不宜通过一句“所有更新都是继续训练”来纠正。应该说明本文采用的是部署替换的广义问题，再指出哪些受控实验额外具备明确训练路径。

### 4.2 读者遇到术语时，还没有看到输入、输出和正确标准

“Banking tasks”不足以说明研究做了什么。BANKING77 是把客户话语归入 77 类服务意图的数据集，包含 3,080 个测试例；它不是仅凭名字就能推断的授信或交易决策实验。[数据作者仓库](https://github.com/PolyAI-LDN/task-specific-datasets)

同样，“function calling”需要说明模型输出工具名和参数，“ToolSandbox”需要说明工具执行会改变可检查的环境状态。读者看见退出数量、AUC 或认证范围之前，应该已经知道每个被统计的对象是什么。

### 4.3 “保留”在不同段落承担不同目标

至少有两项不同承诺：

1. 候选模型继续正确完成原模型已经正确完成的任务。
2. 少量验证得出与完整重新评估一致的判断。

两者可以相互支持，但不相同。完整重新评估也可能告诉我们某个旧任务已经失败；正确识别这一失败，不等于恢复了任务。如果进行修复，完整评估的比较基准还必须明确是修复后的同一个最终模型。

早期 PDF 强调精确复现完整重评结果和下游工作，R140 替换稿更强调旧能力损伤与更新选择。后续整合必须让读者看清这些目标之间的关系，否则会觉得研究对象不断变化。

### 4.4 “可靠”“覆盖率”“拒绝”也有多种含义

| 术语 | 正文首次出现时应解释的含义 |
|---|---|
| 旧要求／旧任务 | 同一输入和成功标准下，原模型已经通过的任务 |
| 实验中的严格可靠 | 例如固定重复次数全部成功；不等于真实成功概率为 1 |
| 损伤 | 旧模型通过而更新模型失败的转移 |
| margin | 当前选择相对最强竞争选择的分数差；具体分数随实验定义 |
| 误差包络覆盖率 | 实际路径误差落入校准包络的比例 |
| 保留声明覆盖率 | 被规则判定可以继续保留的任务比例 |
| 拒绝认证 | 证据不足以作出保留保证；不等于语言模型拒绝回答用户 |

以 R134 为例，98.36%／96.72% 的路径包络覆盖率，与 27/61／29/61（约 44.3%／47.5%）的保留声明比例不是同一指标。图表必须避免让读者把前者理解为几乎所有旧任务都获得了保护保证。

### 4.5 正文替换稿更像审计答复

R140 新文字正确披露了原终点缺陷、匹配指标偏离、聚类、缺失交叠等问题，但在摘要与引言中集中排列这些内容，会让尚未理解问题的读者先阅读项目修订历史。

科学论文开头应先建立问题、具体任务、已有发现和意义。必要的主要限制需保留；详细纠错沿革、内部版本号、job ID 和哈希应在 Methods、SI 或审计档案中可追溯。不能把这些记录从档案删除，也不必让它们占据论文的第一阅读层。

## 6. 下一轮正文应怎样组织

建议在 Results 之前完成以下信息，保持现有正式理论和完整历史母版：

1. **具体场景。**例如部署中的助手原本能正确选择工具和填写参数，候选模型增加处理更复杂请求的能力；问题是旧请求中哪些仍会正确执行。
2. **更新定义。**部署替换不要求知道商业模型的训练血缘；受控实验才研究明确的训练方向。
3. **评价目标。**区分保留任务能力、判断是否保留、以及修复后重新判断。
4. **一个总问题及关联问题。**解释证据、预测、干预和连续更新之间的关系，并明确哪些已经得到结果、哪些还在验证。
5. **简短研究设计概览。**读者在第一张结果图之前就知道用什么模型、做什么任务、怎样判断成功。

概览可使用下表；商业版本与具体任务名必须按最终原始记录填写，不应凭印象补齐。

| 研究部分 | 模型实际做什么 | 更新如何形成 | 主要用途 |
|---|---|---|---|
| 商业版本配对记录 | 对同一批任务生成结果并接受固定规则评估 | 部署候选版本替换；训练血缘通常不可观察 | 描述旧成功集合的进入、退出和返回 |
| 受控函数调用实验 | 根据请求输出函数名和参数 | 同一原模型出发、相同训练配方的不同候选 | 比较新能力与旧损伤，检验局部预测 |
| 有状态工具执行实验 | 执行查询、联系人／设置等任务 | Hermes 模型上的已知更新 | 检查工具／状态终点及方法适用限制 |
| BANKING77 支持性证据 | 把客户话语分类为服务意图 | 按历史材料明确模型／上下文变化 | 展示平均改善与逐例保持的区别 |

每项正式结果仍应保留明确假设和数学结论。读者在定理前需要知道它要解决的任务；定理后需要知道机制、数据支持及适用限制。无需把数学深度改成泛泛解释。

### 可供整合的英文开场示例

以下是表达示例，不是已经合并的最终摘要或引言，也未声称新增实验已经成功。

> An AI assistant may be replaced to handle new requests, follow revised instructions or use additional tools. The replacement must also be assessed on tasks that the deployed system already performs correctly. A higher average score does not identify which of those tasks will remain reliable. For example, an assistant may improve at requests requiring several function calls while losing accuracy on simpler calls that previously worked. We study how to identify such losses, what evidence is needed to assess preservation, and when an intervention can restore old requirements without sacrificing other useful behavior.

### 更新含义的英文澄清示例

> Here, an update denotes the replacement of a deployed model by a candidate model. This does not assume that a commercial successor was trained from its predecessor's weights. We distinguish observations across model releases from controlled experiments in which the starting model, training data and parameter changes are known. Release comparisons establish changes in behavior; the controlled experiments test mechanisms associated with those changes.

### Results 前的方法概览示例

> We combine paired release evaluations with controlled open-weight experiments. In the controlled function-calling study, candidate updates start from a common Qwen2.5-1.5B model and use the same training data, replay composition and optimization budget. We select candidates using new-capability validation before examining their old-task outcomes. Success is assessed by checking the generated function names and arguments against benchmark answers. A separate Hermes-based ToolSandbox study evaluates executed tool traces and resulting states. These studies have different roles: the first compares capability gains with old-task losses, whereas the second examines the applicability and evidence requirements of the preservation procedure in a stateful environment.

以上概览之后，应立即给出主要数据规模、冻结划分和最终成功标准，避免让读者到 Methods 才能知道图中“任务”指什么。

## 7. 黑箱访问和敏感性分析应如何具体化

Fanlin 的黑箱问题不能只用“可以估计参数”回答。应提供一个简短访问条件表：

| 要做的判断 | 需要的观测或权限 | 无此条件时的边界 |
|---|---|---|
| 比较旧／新成功转移 | 同任务输出、真值或可执行判据、稳定评估条件 | 汇总榜单无法识别逐例损伤 |
| 估计任务成功概率 | 合适的独立重复或任务抽样、明确总体 | 固定少量全对不能当作成功概率为 1 |
| 计算 token margin | 适用的分数访问、相同输入与目标定义 | 仅有最终文本通常不足以恢复精确 margin |
| 估计更新方向的局部效果 | 可以施加 pilot 或获得可验证的等价信息 | 封闭 API 的隐藏训练变化不能直接当作已知方向 |
| 按干预权重修复 | 允许执行相应训练／编辑、评估副作用 | 几何可行性结论需限制在实际允许的干预库 |

敏感性分析应回答“结论或动作在哪里改变”，而不是对所有参数机械扫描。优先使用已经保存的逐例记录分析收益门槛、强度网格和校准规模；只有缺少决定性边界的信息才新增计算。尤其应报告保护能力与新收益同时变化的曲线，以及校准成本何时抵消收益。

## 8. 投稿前的优先级与完成标准

**优先级 1：统一交付。**形成真正合并后的现行正文、SI、图表、实际协议及代码；保留全部历史档案。摘要、结论和图注都应使用现行证据范围，旧 PDF 只用于追踪意见。

**优先级 2：修复关键实现与终点。**完成工具任务语义区分；V2 的拒绝认证分支、成本台账、输入一致性和分组规范化；明确新能力验证筛选与最终审计判定的区别。

**优先级 3：完成决定性前瞻实验。**在同一最终模型上同时验证新收益、旧风险和成本，并保留逐例／逐家族结果。8 个候选种子属于一次候选集合，不自动等于整个选择方法被独立重复了 8 次。需要根据目标效应和不确定性要求决定完整重复及最终审计规模。

**优先级 4：重写阅读顺序并验证图表。**先问题和具体任务，再方法概览和结果；术语首次解释；正式数学不削弱。让非本领域合作者只读开头与第一张图，就能复述“谁在做什么、什么算失败、作者发现什么、为什么重要”。

包外 V2 的 full-update 和 simple-scaling 规则，在存在合格完整更新时会选中同一个最高能力候选，因此这两个标签不总提供独立比较。还应纳入真正具有不同机制的合适基线，并提前固定选择规则。已有协议尚未落实其蓝图中所有遗忘预测／兼容性方法，不能用几个相似选择规则替代最接近文献的对照。

**当前投稿判断：问题仍然重要，R140 的纠错值得保留；但科学增量、可执行控制证据、完整交付和跨学科叙事仍有明确缺口。**改善可读性会让已经完成的研究被正确理解；完成上述关键实验才可能提高文章能够主张的科学贡献。两项工作应在下一轮共同推进，并以可检查的结果结束，而不是再增加一个只包含修订说明的版本号。
